About

I'm a Software Engineer with 7+ years of experience across distributed cloud-native systems, backend infrastructure, AI and platform engineering at companies ranging from early-stage startups to large-scale enterprises.

My current focus at AFG is Core Billing Infrastructure specifically the payment gateways, simulation pipelines, HPC workflows, invoice storage routing, cache invalidation, and consistency guarantees or services operating at continental scale. payments infra · internal platform · 2020–2022
< 4 hrs SLA -94% failure rate
▼
Summary

End-to-end redesign of a payment gateway platform that ingests billing data from upstream Policy Invoicing systems, orchestrates ACH and digital payment processing through the OneInc payment provider, and throttles all outbound payment requests through AWS SQS to sustain throughput at scale for 150,000+ active policyholders.

Problem

The legacy system suffered from P99 latency spikes above 2 seconds during peak traffic, lacked consumer group isolation, and had no replay capability. Incident postmortems repeatedly traced root causes to the messaging layer. On-call load was unsustainable.

expected-value-calc
sports-betting · personal · 2023–present
SaaS · 2000+ users
▼
Summary

EdgeCalc is a self-funded passion project designed to bring data-driven decision-making to casual sports bettors. The system is built on a fully serverless AWS infrastructure for minimal operational cost. Python Lambda functions handle all computation and data management. The React frontend is a static SPA served from S3 via CloudFront. The entire backend scales automatically to support up to 2,000 concurrent users without any manual intervention.

Problem

It addresses a fundamental problem in sports betting: most bettors place wagers without knowing whether the odds offered by a sportsbook represent positive or negative expected value relative to the true probability of an outcome.

Architecture Overview
Request → [Local Process Cache (1s TTL)] ↓ (miss) [Regional Redis] ←→ [CRDT Sync (gossip, 50ms interval)] ↓ ↑ [Quota Decision] [Cross-region peers (3 DCs)] ↓ [Allow / Throttle / Degrade] Fallback: local in-mem counters on Redis failure Consistency: AP (eventual), 2% tolerance window
